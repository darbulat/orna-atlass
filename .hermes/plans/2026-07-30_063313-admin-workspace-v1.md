# Admin Workspace v1 Implementation Plan

> **For Hermes:** Use large-feature-delivery and test-driven-development to implement this plan as
> verified vertical slices. Do not begin product code until `specs/admin-workspace-v1.md` is accepted
> and its open questions are resolved.

**Goal:** Deliver an admin-only ORNA Atlas web workspace for browsing and editing editorial data,
operating the existing media pipeline, reviewing audit events, and—behind a separate production
gate—managing roles and memberships safely.

**Architecture:** Add bounded admin read contracts without widening public DTOs. Keep mutations in
their responsible domain services, add an allowlisted audit event in the same service-owned
transaction, regenerate OpenAPI types, and implement one backend-to-browser workflow at a time under
`web/app/admin`. Authorization remains backend-enforced through DB-resolved `get_current_admin`;
frontend guards are UX only.

**Tech Stack:** FastAPI, Pydantic v2, async SQLAlchemy/PostgreSQL, existing Redis/RQ/S3 integrations,
Next.js App Router, React, TypeScript, generated OpenAPI types, Node test runner, Playwright.

**Source specification:** `specs/admin-workspace-v1.md`

**Delivery tiers:**

- **Tier A:** foundation + read-only admin workspace.
- **Tier B:** editorial mutations + processing controls.
- **Tier C:** role/membership management behind an independent production gate.

Tier C must not be inferred as approved merely because Tier A/B are accepted. Freeze the exact tier
before RED.

## Risks and trade-offs

- **Large cross-layer scope:** mitigate with tiered vertical slices and exact GREEN after each one.
- **Sensitive admin DTOs:** no-store, server auth, fail-closed parsing and public projection canaries
  are release blockers.
- **Offset pagination drift:** accepted for v1 with stable ordering and “Load more”; cursor pagination
  is a follow-up if write volume makes drift material.
- **Role lockout:** Tier C cannot ship without real PostgreSQL concurrency evidence.
- **Audit signature churn:** pass one bounded actor context rather than adding unrelated router logic;
  still keep transaction ownership in domain services.
- **Managed-key media UX:** operationally useful but not a browser upload. Label it truthfully and do
  not imply the browser transferred a file.
- **Archive irreversibility:** deployment rollback does not undo committed archive/role/membership
  changes; UI copy and handoff must say so.
- **Test duration:** run narrow RED/GREEN per workflow, reserve time for one complete frontend and
  backend cycle plus exact-head CI.

## Completion definition

Use only one of these handoff states:

- **Complete and verified:** every accepted tier exists, required checks passed, exact-head review and
  CI are green, approved SHA is deployed and non-destructive production smoke passed.
- **Implemented, verification blocked:** code exists but exact named dependency/check is unavailable;
  do not claim completion.
- **Partial:** name only delivered/green tiers and list deferred tiers explicitly.

The handoff must include user-visible outcome, files/layers, invariant and acceptance coverage,
commands/results, migration and OpenAPI impact, security/privacy notes, rollout gate state, remaining
risks and unrelated worktree changes intentionally preserved.
